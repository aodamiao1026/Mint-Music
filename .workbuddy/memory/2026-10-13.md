## iOS 适配验证与修复

背景：用户要求"适配 iOS"。摸底发现仓库已有大部分 iOS 基础（AppDelegate + 3 个原生 Handler 镜像 Android MainActivity 通道、Info.plist 权限齐备、CI build-ios.yml）。实际缺口在构建配置层。

### 修复内容
1. `ios/Podfile`：post_install 中把所有 IPHONEOS_DEPLOYMENT_TARGET < 15.0 的 Pods 抬到 15.0（Xcode 27 只支持 ≥15.0）
2. `ios/Runner.xcodeproj/project.pbxproj`：Runner 部署目标 13.0 → 15.0
3. `lib/features/settings/data/settings_service.dart`：getDownloadDir 默认值平台自适应（iOS 沙盒 Documents/MintMusic，Android 保持 /storage/emulated/0/Music/MintMusic）
4. README/CHANGELOG 更新为跨平台描述

### 重要环境结论（本机 Xcode 27 / macOS 27）
- actool "Failed to write to CAR"（BOMStorageCompact rename EPERM）是 DerivedData 污染导致的环境问题，彻底删除 ~/Library/Developer/Xcode/DerivedData/Runner-* 后消失；与 Pods 无关，无需剔除 DKPhotoGallery 资源
- 构建/analyze 需绕过沙箱运行；WorkBuddy 沙箱会拦截 DerivedData 与 ~/.swiftpm 的删除
- git stash 事故教训：flutter analyze/pub get 会重新生成 xcconfig 导致 stash pop 冲突；用 `git checkout stash@{0} -- <files>` + drop 兜底

### 验证结果
- flutter build ios --debug/--release --no-codesign 均成功（Release 52.8MB）
- flutter test 57/57 通过；analyze 无新增问题
